    Stream

    Network

    Dante Controller finds AES67 streams through SAP. Turn on AES67 mode on the receiving Dante device, then the stream appears as a receivable flow. For ST 2110 receivers, download the SDP file instead.

    Read delay: audio reaches MXL some time after its timestamp, roughly one NDI audio chunk. The sender reads this far behind and moves its RTP timestamps forward by the same amount, so packets leave just after their timestamp. Keep it above the "Arrives from MXL" figure. Dante receivers then only need a normal latency, set by "Leaves after".

    Send delay: added on top of the sender's own buffering, about 1 ms. Set it to -1 so packets leave at their timestamp, which is what a 1 or 2 ms Dante latency needs. It can go to -2.

    Changing the channel count restarts every function, because it is set where audio enters MXL. Other changes only restart the AES67 output.

    Role

    Profile

    The PTP function steers this VM's system clock, which is the clock MXL and the AES67 output run on. NTP on the VM has to be off, or the two will fight. setup.sh offers to turn it off.

    With only software timestamping (a virtual NIC), offsets are much larger than with a NIC that timestamps in hardware. Good enough to learn the workflow, not for sample-accurate sync.

    Applying restarts PTP, waits for it to settle, then restarts the media functions, because the clock may step.
